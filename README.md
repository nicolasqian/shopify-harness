# Shopify Harness

本仓库维护 EcoFlow US Shopify 主题的代理规则、技能、项目地图和性能文档。文件从本仓库根目录起按主题项目的相对路径存放。主题项目中的副本供 Codex 和 Claude直接读取。

## 日常更新

在 macOS 或 Linux 上安装 Git 和 Python 3.7+，将本仓库与主题仓库放在同级目录。在本仓库根目录运行：

```sh
git pull --ff-only
./sync-to-theme.py --dry-run ../ecoflow-tech
./sync-to-theme.py ../ecoflow-tech
```

首次使用空远端时，先由维护者提交并推送初始内容，之后其他人即可拉取。主题工作区已有相同内容时，首次同步只建立本地基线。新工作区缺少清单中的文件时，脚本会补齐。预览模式不写文件。

## 修改或新增内容

1. 在本仓库直接编辑对应文件，例如 `.agents/skills/` 下的技能。新增文件时，在 `manifest.txt` 加入对应的主题相对路径，每行一个文件。主题当前分支须忽略该路径。
2. 运行上面的预览和同步命令，在主题项目里验证规则和技能。
3. 在本仓库评审差异、提交并推送。主题仓库继续沿用自己的 Git 工作流。

清单包含 AGENTS.md、CLAUDE.md、三个技能及配套文件、项目和性能文档，以及相关历史证据。历史报告中指向特定机器或临时目录的记录保留原文。日常采样、临时输出和导出继续保存在主题工作区。

## 冲突和停止维护

脚本预检整份清单，通过后才开始复制。它通过主题工作区的 `.tmp/shopify-harness-sync.json` 记录上次同步的内容摘要和执行权限。主题副本被本地编辑或删除、首次遇到不同内容、目标已被 Git 跟踪或未被忽略时，脚本会列出冲突并退出。

例如主题里改过项目地图，在本仓库执行：

```sh
git diff --no-index -- docs/project-map.md ../ecoflow-tech/docs/project-map.md
```

将要保留的编辑合并到本仓库的文件中，核对后让两份文件一致，再重新同步。若本地删除是有意的，从清单和本仓库中移除对应文件。移出清单后，脚本保留各主题工作区的旧副本，由维护者按需清理。若同步中断，重新执行即可。若清理了基线文件，下一次按首次同步处理。
