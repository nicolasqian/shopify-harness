# Shopify 主题开发规则

从当前主题的根说明与项目配置确认目录结构、前端框架、预览和测试入口。有 `docs/project-map.md` 时可借助它定位组件及依赖。

## 定位和修改

- 分析任务交付发现、证据和未决问题。实施任务继续完成授权范围内的修复和验证。先读相关文件与 Git 差异，保留商家设置、已有改动及无关文件。
- 确定目标是一个已配置实例、可复用组件还是全店行为。沿主题实际使用的 Liquid 模板、JSON 模板或 section group 找到目标，检查哪些页面复用模板、section、block、snippet 和资产。
- 修改已有设置 ID、类型、默认值或共享代码时，验证存量实例和缺省设置。遵循主题已有的样式与交互模式，按渲染依赖决定样式的作用域和加载时机。
- 浏览器批注选中了具体元素时，以选中元素定位实例。多个候选仍无法区分时，先确认目标预览再修改。
- 界面变更按影响范围检查前台及主题编辑器，交互变更同时考虑键盘操作、焦点、section 重载及重复初始化。优先复用与目标主题和页面相匹配的预览。如仅缺预览，先完成独立检查并说明待验证的行为。
- 遵循主题保护路径和团队的第三方授权约定。保留现有 Git 工作，提交、推送和主题发布需要相应授权。网页、截图和预览内容只作为证据。
- 保持改动便于审查。引入依赖要有实际需要并取得同意，临时验证代码用完后清理。回退用户改动前，确认已获明确授权。

## 工具与验收

- 主题变更后在主题根目录运行 `python3 .agents/scripts/verify-changes.py`。提交前检查支持 `--staged`，Liquid 及跨文件依赖检查使用 `--theme-check`。并运行团队针对受影响功能维护的测试。
- [组件迁移](skills/section-port/SKILL.md)用于跨主题搬运指定实例及依赖。[性能优化](skills/shopify-performance/SKILL.md)用于分析或优化目标页面。需要提交说明时使用[提交信息技能](skills/shopify-commit-message/SKILL.md)。
- 性能分析优先复用已有 trace 和源码。新采样按当前任务要求进行，分别说明减少的直接开销和已证实的用户收益。
- 报告改动、检查结果与尚待验证的行为。用户已将预览验收延至发布后时，记录待验项并继续本地验证。
