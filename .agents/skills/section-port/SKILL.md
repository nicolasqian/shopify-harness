# 搬运主题组件

范围：只搬运用户指定的组件实例到目标主题。包括对应的 `sections/*.liquid`、模板 JSON 配置，以及运行所必需的 snippet、CSS、JS。不要顺带搬运同类型的其他实例或改动无关模板。

## 流程

1. **定位实例**：确认源/目标仓库、模板和组件；按源模板 `order` 找到对应 section ID（包括 disabled）。有多个候选且无法确定时，列出名称与位置，请用户选定。需要时可用 `scripts/extract_section.py --help` 查看提取方式。
2. **比较目标**：读取源 section、配置和引用的 snippet、CSS、JS；对目标同名文件及可复用实现做 diff，并查找它们在目标主题中的引用。按下表选择处理方式。
3. **最小落地**：复制该实例的配置和必要代码，保留目标模板的其他内容。外置样式或脚本只迁入实际依赖部分；跨组件联动需确认相关 ID 和事件在目标页面有效。
4. **验证与交付**：检查 JSON/Liquid、依赖引用和 diff；有预览链接时验证桌面、移动端及交互。执行结束后，逐项列出实际动作（如新增、复用、补齐、覆盖、跳过），注明涉及的文件或配置及原因；报告 Theme Editor 名称、section ID、验证结果和待处理项，不把计划或未完成事项列为已执行。

## 目标已存在时

diff 用于判断功能、schema 和依赖差异，不把源文件的每一处差异都同步到目标。

| 情况 | 处理 |
|---|---|
| 目标没有实现 | 新增组件及缺失依赖。 |
| 目标已有所需功能，配置兼容 | 复用目标文件，只迁入指定实例的配置。 |
| 仅缺少小部分功能，可保持旧行为 | 局部补齐；新增设置的默认值保持目标原有表现，并检查已有调用。 |
| 结构、schema 或行为不兼容，或无法确认对其他页面的影响 | 新建独立变体，仅让本次实例引用它；同步调整必要的依赖与命名。 |
| 用户明确要求全量覆盖 | 先说明将丢失的目标定制及受影响的调用；覆盖范围明确后执行，范围不清时再询问。 |

同样的规则适用于 snippet、CSS、JS。同名不代表同功能；目标有未提交修改时，以当前文件为准保留其改动。默认不全量覆盖，也不整份替换共享 `theme.js` / `theme.css`。

## 边界处理

- **重复迁移**：目标已有同一实例且配置一致时跳过；无法确定是更新还是新增时才询问。新增实例使用不冲突的 section/block ID，并更新本次迁移范围内的关联引用。
- **配置差异**：保留目标已有实例的配置；新实例使用源配置。目标 schema 不支持的设置或 block 不得静默丢弃；优先使用兼容变体，必要时说明缺口再确认取舍。保留模板注释、已有顺序和无关内容。
- **共享依赖与联动**：递归检查必要依赖；复用目标已有库，避免重复加载、重复事件绑定或重复注册 custom element。独立变体需检查全局选择器、元素名称和 ID 冲突；联动依赖另一个 section 时，先找目标对应项，需要扩大搬运范围才询问。
- **跨店铺资源**：核对图片、商品 handle、variant ID、域名链接、metafield 和应用依赖。无法映射时列为待处理，不编造目标值；`shopify://shop_images/` 需在目标 Files 中存在同名文件，下载图片不等于已上传。
- **范围与验证**：仅要求搬组件文件时，不自行加入模板；外置 CSS/JS 默认保留组织方式，用户要求时才内置。共享代码被修改时验证已有调用；缺少预览或店铺资源时，明确哪些表现尚未验证。
