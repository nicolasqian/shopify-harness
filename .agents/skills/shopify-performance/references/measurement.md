# 按需测量口径

仅在用户明确要求测量或发布后已要求性能核验时读取；这些是数据解释规则，不是每次优化必跑的清单，不规定采样次数。

- 遵循仓库预览规则，优先已有入口及可用浏览器 skill。确认最终 URL、主题 ID/role、模板、变体及修复代码确实生效。正式域名也可能因预览cookie显示开发主题，不能仅凭域名认定是正式站。旧预览域名、旧代码或尚未同步不能用作修改后结果。
- 核对内容版本时，同时记录区块启用状态、卡片数量及相关输出；文件哈希相符不能证明不同主题的配置相同。发布后重新核对正式 role 和实际代码，单独记录线上结果；缺少同内容正式基线时，不把开发预览与线上数字拼成收益对照。
- 同一受控批次保持 URL/最终变体、代码版本、设备/UA、真实布局视口、网络/CPU、缓存/Service Worker、会话和观察窗口一致。采样期间不交互，不并发浏览器采样或重 CPU 分析。
- 排查移动端横向溢出时，结合 `document.documentElement.clientWidth`、`scrollWidth`、元素边界和截图判断，不只比较 `scrollWidth` 与 `innerWidth`；溢出可能使移动端布局视口扩大，掩盖异常。
- 先确认功能和改动输出有效，再启动必要的性能采样。使用新入口、采集器或环境时先跑一个样本，确认页面、paint、视口、数据落盘和分析正常，再扩大批次。首样本失败先定位，不连续跑完整批次来重复同一错误。功能验证等待目标组件及媒体就绪，不默认等待整页load/complete或所有第三方资源结束；性能观察窗口另行固定。
- 只补测具体无效样本；同一天、相同入口/条件且相关代码一致的基线可复用，注明来源。导航超时先检查最终状态，跳转期间DOM可能暂为空；每条样本及时落盘，保留失败及补验记录，避免批次末尾异常丢失先前结果。
- 指标慢是有效结果，不按表现剔除。HTTP 错误、验证页、后台不可见页面、错误布局视口或被干扰导航应标为无效，保留原因。
- 观察窗口内没有FCP/LCP的样本不能计算相应中位数，但仍是必须披露的失败/超时结果。区分已证实的采集环境问题与尚未排除的页面问题，不能把所有NO_FCP直接归因于环境。报告有效/总样本数、观察上限和全部补测；补足有效样本不抹除失败，也不因此宣布整体验收通过。
- 明确每条时间数据来自观察时间线还是 Lighthouse 模拟结果，不把 observed LCP 子阶段与模拟 LCP 混加。响应开始不等于 HTML 已可解析；涉及早期响应或分段交付时，同时核对最终响应、正文到达和资源发起时间。
- 区分 PSI/Lighthouse 实验室数据与 CrUX/Shopify 真实用户数据。缺失 TBT/INP 记为无数据；固定窗口阻塞时间不能替代 TBT 或 INP。
- 验收阈值同时报告逐条结果、中位数、范围和达标样本数。中位数达标不能写成稳定全部达标；低中位 CLS 也不能掩盖严重位移样本。结果必须对应最终保留代码，收尾修改后旧批次降为候选记录，按影响补验，不用旧候选最好成绩替代。
- 输出中位数、范围、可计算样本数和直接机制证据。小样本范围重叠时不宣称稳定提速；独立子阶段的中位数不能相加当作 LCP 中位数。
- 普通导航优先。CDP 文档响应拦截会改变 TTFB 和流式解析，只适用于明确需要的隔离诊断；不能把这种实验的绝对秒数当正常导航收益。
