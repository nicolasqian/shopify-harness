# EcoFlow 主题的实测经验

这些包括 US 性能任务（含2026-10-08 Prime Day发布回归）及 UK M10 Stories 页面任务（截至2026-10-06）的历史案例，供判断机制和避免重复实验。最新状态以当前任务、仓库 TODO 和代码为准，不固定预览 URL、主题版本或数值。历史原始报告与采样已于2026-10-22按用户要求移出 docs（若当前主题仓库存在 `docs/HANDOFF.md` 可查恢复入口）；本文保留可复用结论，不要求日常任务重新读取旧报告。

> 2026-10-11：下文案例及其采样次数均为历史证据，不是开发阶段前置条件。执行策略以仓库 AGENTS.md 和 SKILL.md 为准；按候选只读相关段落。

## 工作量与验收

- 本轮P0有6个阶段，整体验收完成2项；P0-04代码子项4/5，不能把两个分母合并成总体完成率。P0-05两项独立改动通过也不能代替评论、隐藏面板及完整购买场景验收。最新完成状态仍应查TODO/HANDOFF，历史数字不作为固定进度。
- 用户先排除404的Outdoor Sale，随后暂停P1，最后暂停所有非P0工作。接续必须沿用最新范围；已经整理出P1/P2候选不代表仍授权执行。`perf.md`当时是用户文件，没有纳入优化改动或清理范围。
- 最初 16 个入口各三次全站基线，随后 CSS、资源裁剪、跨域补测与多轮功能回归占用了大量时间。用户明确批评测量多、代码产出少。已有证据时应开始修改；同一个明确的小改动不要反复证明或测遍全站。
- P0-02 最终按用户接受的边界收口：资源和功能通过，TBT 收益未证实。不要重新打开已完成任务来补无法取得的指标。
- 该受控实验使用 CDP fulfill 整份 HTML，TTFB 约 15 秒且失去流式解析；它证明特定文档交付下资源差异，不能用其绝对 FCP/LCP 对比正常线上导航。延长观察至 90–120 秒仍不能稳定得到 TBT，不要无止境延长或把缺失当零。

## 图片、样式与首图

- 非首屏图片懒加载得到直接请求收益：U01 远端图文区首图前请求 3→1，U02 说明 Tab 5→0，U03 独立远端图 1→0。需要滚动/Tab 后实际显示，不应为这些动作附加全站购买流程回归。
- U03 全轮播懒加载曾使远端请求 8→1，但最后一张切换等待过长，候选撤回。减少初始请求不能以损害首次切换体验为代价。
- 主图减小、CSS 内联、布局子集、已有 preload 移位和多种 U03 图片 preload 候选已有失败记录。特别是布局子集引发晚期 LCP 回退。没有新机制或环境解释时不重复。
- 新的三个区块 CSS 提前发现与失败的主图 preload 移位不是同一机制。U01/U03 针对产品和模板提前发现 `cust-product-template.css`、`component-rating.css`、`install-services.css`，确认每个样式仍只有一个请求，完成时间提前。LCP 样本范围重叠，因此可陈述直接样式收益，不能承诺同幅度正式站提速。
- U03 的 900/1240 图片双请求在该样式候选前后仍出现，不能标为解决。preload 判断要匹配实际 `currentSrc`、变体媒体和实际请求，不只比较标签里的 fallback `src`。
- U01/U02 的绘制时间与 ConsentManager 同步脚本、theme.css 较晚完成者相关。时间线是定位线索，不足以证明唯一因果；第三方时机调整移交业务确认。

## Prime Day：指标目标、批次与发布回归

- 移动KV传输约134KB→60KB、首屏发现提前，属于直接机制收益；开发候选曾达到黄色LCP，但最后代码批次仍有慢样本，正式发布回归也未稳定达标。不能用上一候选最好成绩或卡片计算减少替代最终LCP验收。
- 最终正式三条中有严重CLS样本，即使另外两条和中位数较低也不能宣称布局稳定。PageContainer/移动导航是位移对象，触发代码尚未隔离；logo已有尺寸，不能凭审计提示继续盲加尺寸。
- viewport提前后，跨断点刷新会话仍记录两档移动图；三条普通移动冷启动却均只有正确图一次请求。分别记录冷启动、切换、切换后刷新及UA/布局视口，不把某一路径的额外请求当作全部访问的LCP原因。媒体匹配与标签顺序正确不能代替网络验证。
- 开发10商品区块与正式11区块不同，不能拼成发布前后收益。发布后实际theme.id/role、模板、配置和代码输出均需重新核对；Git干净或用户已发布不代替实页验证。
- 顶部Web Only锚点保留，但对应区块disabled、目标DOM不存在，点击只改变选中状态。导航验收需确认目标存在及实际定位结果；该配置问题不自动归因性能改动。
- 收尾修改后应重开待验项并更新最终批次。此前提前报告100%、多个“最新/最终”记录并存，使状态不够清楚；后续将代码完成、功能覆盖和指标达标分别记录，顶部只保留当前结论。

## Owl、占位和图库

- `layout/theme.liquid` 根据实际组件标记限制 Owl，编辑器保留依赖；U03 需要 Owl，而 U01/U02/U04/U05 的测试模板不需要。jQuery、Bootstrap 和其他图库仍有业务依赖，不能一起删除。
- 图片 `complete` 和 `naturalWidth` 正常仍可能显示灰块：检查包装层 `.ef-media-ph` 的 `is-loaded` 和 `::before`，并看截图。隐藏媒体加载时就绪检查跳过，显示后缺复查；复制 HTML 绑定标记也不能保证复制了监听。
- 修复使用 DOM 节点属性绑定监听，并在 Owl initialized/translated/refreshed/resized 后检查当前轮播。验证应由页面自然执行，手动调用 binder 消除遮罩只能用于诊断，不能冒充修复通过。
- 桌面 U03 原样式隐藏 Owl、显示 stacked；不要点击隐藏的 Owl 控件。移动主图库用圆点，桌面用缩略图；动态变体媒体可能没有预期的 data-media-id，可核对实际图库选中索引、图片和表单变体。
- 首次图库复用 JS 候选没有证明 LCP 收益且出现退化，已恢复本地与开发主题；不要把失败 JS 的 AFTER 当成其他候选基线。相关原版数据在代码/条件一致时曾复用于独立 CSS 候选。

## UK M10 Stories：轮播首帧与响应式初始化

- `page.m10-stories.json` 使用 `story-slider-v2.liquid`。轮播接管前，各张卡片按普通块级元素纵向堆叠，接管后横向显示；只看加载完成后的页面会漏掉首帧问题。该页 Custom CSS 增加初始化前的横向可滚动布局及必要容器定位规则，初始化后退出 fallback。禁用脚本验证中，桌面和手机的三张卡片处于同一行；自然加载后轮播切换和弹窗仍可操作。该实验验证静态 fallback，未覆盖所有慢加载竞态，也未测量 CLS/LCP/INP。
- Flickity CSS 使用 `media="print"` 配合 `onload` 异步启用，这是需要检查的加载环节；没有隔离证据，不能仅凭异步加载存在就认定它是唯一根因。补充基础布局应限定实际消费页或组件，不默认改变全站依赖加载方式。
- 轮播对齐原先只在初始化时按宽度计算，手机切换到桌面后仍左对齐。按当前组件断点监听变化并更新布局后，跨断点恢复居中。CSS 与 JS 应使用一致的断点条件；本次 749/767px 差异是该页面案例，不是所有主题的统一断点。
- 平板社交卡片的固定图片宽度挤压文案列；320px 公共页头另有溢出。检查前者的容器内部越界及后者的文档横向溢出，不能只检查整页宽度。320px 时 `innerWidth` 曾随溢出扩大，比较 `scrollWidth` 与它会漏报；结合根元素 `clientWidth`、元素边界和截图才定位异常。
- 旧预览未同步组件配置时，临时注入最新样式仅用于候选验证；新预览同步后才做真实页面复验。模板配置、组件顺序和样式输出都是版本核对依据，不能以临时 DOM 结果宣布开发主题已修复。
- 一次手机加载出现 MutationObserver 报错，后续桌面复验未复现，来源未确认。应保留该覆盖边界；未复现不等于已解决，不能自动归因第三方。跨域视频 iframe 内的 Escape 限制也不能从父页面关闭按钮正常推断为已修复。

## 交互与模板导航

- 移除 `_updatePrice` 内只服务于已注释条件的 JSON 解析：U01/U02/U03各3次真实选项切换，精确payload解析8→6，事件仍为2次，所选主变体正确。AFTER记录价格和主图，但BEFORE没有这些字段，不能声称未记录字段已做严格前后对照。临时解析计数器只包裹目标payload，检查后恢复原生方法；不要把所有JSON.parse计数混作价格解析收益。证明的是计算减少，没有测 INP 就不宣称 INP 提升。
- U04/U05 有业务需要的 `?view=` 跳转。使用 `URL.searchParams.set` 修复重复/错误 view，保留 variant、追踪参数、hash 和 quick-view 条件。证明参数修复，不声称消除了必要跳转或稳定快几秒。
- App/GTM 同时存在并不证明重复上报；Preciso 特定模板的 jQuery 与主题 jQuery 分开审计。

## 非首屏视频

- U03 Smart Home Panel 2区块离首屏约8000px，原版仍请求桌面和移动MP4。目标商品、模板、section三重限定后，接近视口只挂载可见来源，保留既有占位和非目标区块；隐藏Tab、断点隐藏和离屏暂停，返回恢复。快速Tab往返可能在play Promise尚未结束时发生，需检查中断后能恢复且不无限重试拒绝的自动播放。
- 观察窗口内两条目标MP4请求2→0；原版第三次请求发生在LCP之后，不能把三次都写成LCP前请求。移动/桌面播放、Tab往返/快速切换、离屏暂停通过，编辑器生命周期和低功耗策略未专项验证。
- 前后LCP中位数9.750→7.440s，但AFTER有效/总样本为3/5，另两次45秒内NO_FCP，并有33.959s有效慢样本。保留直接资源优化不等于稳定提速或排除了页面故障。用户追问时给出采样商品页和具体区块，说明异常指整页无首屏绘制，而不是认定视频播放失败。

## 购物车测试与恢复

- U01正式站加购触发自动优惠，原有商品line key变化；按旧key/新key区分测试项曾误删原商品。已恢复原variant、quantity、key和金额。这证明key不是测试前后稳定的商品身份，不能只凭key变化清理。
- 测试前保存variant、properties、selling plan及数量；同variant不同properties可能是不同商品，同一身份再次加购也可能合并数量。清理前读取最新cart，使用当前key操作已确认身份，仅恢复数量差额。已有优惠、赠品和未知商品不能当作可删除测试数据；恢复失败时停止后续测试并报告实际差异。
- U03开发购物车原为空，加购的商品自带`Shipping: ''`属性。脚本最初假设properties为空而停止清理，核实身份后只移除该测试项并确认空车。不要要求测试商品properties必为空；校验应对照实际表单和本次加入的身份。
- U01安装服务checkbox关联绑定条款，本轮仅验证UI显示，未勾选；不要将“服务面板存在”写成安装服务购买验收完成。

## 浏览器与采样陷阱

- 预览域名会变，主题同步可能停止。先验证源输出和实际 role；历史链接失效时找当前入口，不假设 localhost 端口，也不擅自发布。
- 在正式域名打开开发主题preview链接后，后续同域导航仍可能显示开发主题。每批记录实际Shopify.theme.id/role；域名相同不能证明是正式站，同一天预览与线上数字也不能拼成因果前后对照。
- Ego原生窗口曾显示用户GitHub旧内容，而任务页有DOM和网络却无paint。确认已有任务空间的实际显示，遵循浏览器skill在同一空间恢复，不通过创建新空间或操作用户GitHub来重测。该已定位环境问题不能自动解释后续每个NO_FCP。
- 全文档 load 可被第三方拖住。功能动作等待主题组件真正就绪；组件初始化前点击可能被后续重建覆盖。超时后检查当前状态，不盲目重试或重复采样。
- 活动页采集曾因等待document.readyState=complete而整批超时，Home Backup Sale的目标图片和9个商品卡控制器实际已就绪。不要把load超时写成404；核对HTTP、title、模板与目标组件。Outdoor Sale独立核实为404，按用户要求跳过；改等待条件后先验证一个样本，不直接再跑整批。
- 点击图片中央可能命中箭头容器。先检查命中元素或截图再换操作位置，不把一次错误定位当代码回退。
- DOM/变体变化后 snapshot ref 可能过期，重新观察后选目标。滚动锚点可能平滑移动而不改变 hash；验证目标位置，不使用错误断言。
- 实际布局视口曾变成 438×948、1560×3376，即使设置参数为 390×844，也必须检查 `innerWidth/innerHeight` 和可见状态。不以设备参数设定成功替代采样有效性。
- `DOMRect` 在采集器中曾序列化成 `{}`；要显式提取 x/y/width/height 等数值。没有字段就不能证明位置稳定；若它不影响候选判定，无需因此重跑整批。
- Lighthouse network records 的 rendererStartTime/networkEndTime 已是毫秒；注意 trace、CDP 时间戳与 performance 时间基准，避免再次乘 1000。改分析脚本时优先从已有 trace 重算，不重新访问页面。
- TBT 曾因 `NO_TTI_CPU_IDLE_PERIOD`/`NO_TTI_NETWORK_IDLE_PERIOD` 缺失。记录可算样本数和原因；固定 FCP→30s 阻塞窗口只作补充。
- 全仓 Theme Check 曾因 Node 内存不足失败，反复同样重跑没有价值。按改动风险做局部语法/适用检查；如做隔离前后比较，要说明既有或缺依赖提示，不能宣称全仓零错误。
- UK M10 的多轮定向 Theme Check 使用了不同文件和依赖集合，问题数量随范围变化。缺失 locale、asset 或模板引起的隔离环境提示，应与真实源文件既有问题分开；相同依赖集合中的新增为零，只证明未检出新增问题，不代表检查退出码为零。
- 有文件保留 CRLF；必要时使用 `git -c core.whitespace=cr-at-eol diff --check`，不要为通过检查批量格式化。`docs` 被 Git 忽略，报告没有进入 git status 不代表没保存。

## 全站阻塞样式拆解与 2026-11 黑五专项

- 当时的 EcoFlow 样本观察到渲染阻塞的 `compiled_assets/styles.css` 与 HTTP 103 Early Hints。拆解时发现 `product-card-carousel` 的覆盖规则也被首页 `hp-senario-cards` 使用，需要在对应的共享或首屏样式中保留。复查其他页面时，按其实际渲染树、响应头和样式依赖判断。[Shopify 样式按页分发说明](https://shopify.dev/changelog/posts/automatic-css-subsetting-for-stylesheet-tags)
- `{% render 'snippet' %}` 会隔离父级 `section` 上下文：切勿在 snippet 内部直接写 `section.index` 判断首屏同步加载，必须由调用方显式传入 `section_index: section.index`（已在 `/pages/subscribe` 的 `custom-modal-section-assets.liquid` 验证）。
- 原 `{% stylesheet %}` 中含相对路径 `url(../assets/...)` 的规则，迁移为外链 `assets/*.css` 时与原编译包处于同级路径可正常解析；若改为内联 `<style>` 则会按页面路径解析导致图片 404，含相对 `url(...)` 的样式必须外链化。
- 判断 `section.index` 的首屏同步条件时，避免把 `or` 和 `and` 混写在同一行，统一使用 `{%- liquid -%}` 显式赋值布尔变量（Liquid 按从右向左结合求值）。
- Shopify 预览模式（`preview_theme_id` / preview cookie）会额外增加约 `54–93 KB` HTML 传输体积、注入 Preview Bar（推高 TBT），且 Cloudflare 边缘 `103 Early Hints` 仍按线上正式主题缓存。预览链接仅适合验证功能、DOM、请求消除，真实 FCP / LCP / TBT 收益须在发布后的正式 URL 复测确认。

## 留下可接续的结论

用四种状态表达结果：直接收益与功能通过；直接收益通过但整体指标未证实；候选无效/回退已撤回；受权限或业务确认阻碍。让下一轮知道该改哪个代码点、哪个假设已失败，以及需要什么证据才能重试。避免只留下大量 raw 文件和“尚未完成”。
